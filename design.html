1 Abstract

Electronic devices are being replaced faster than they are repaired or recycled. The Global E-waste Monitor 2024 reports 62 million tonnes of e-waste generated worldwide in 2022, of which only 22.3% was documented as formally collected and recycled. In India, reported e-waste generation reached 1.751 million tonnes in FY 2023-24. Many discarded phones, chargers and earphones are still repairable, but users lack quick, trustworthy information about repair costs and safe disposal channels.

TechCycle is a mobile-first web platform that keeps electronics in use for longer. A transparent repair-or-replace engine scores repairability from 0 to 100 using repair cost relative to a new device, remaining device life and the fault's typical fix success rate. It then estimates the cost in rupees, the savings and the CO₂e avoided. Users can find nearby repair shops, refurbishers, collection points and recyclers on a map, book a doorstep pickup or drop-off with a trackable ID, buy or list tested spare parts and refurbished devices, and view a dashboard of their verified impact. A partner console lets technicians and recyclers move each request through a defined workflow, and recycling requires a data-wipe checklist and ends with a disposal certificate.

The Milestone 2 build implements all six modules as a working prototype (HTML, CSS and JavaScript, with browser storage), backed by an automated test suite that runs live on this page. Milestone 3 will add a backend, partner verification and real partner data from a survey of shops near campus.

Keywords: e-waste, right to repair, circular economy, repair-or-replace decision, SDG 12, web application

3 Problem & objectives

Problem (from Milestone 1)

  • Unnecessary disposal: repairable phones, chargers and earphones are thrown away.
  • High (perceived) repair cost: users assume replacing is cheaper.
  • Poor e-waste recycling: devices end up in regular waste instead of formal channels.
  • Environmental pollution: hazardous substances are released and valuable materials lost.

Stakeholders

Students and young users, households, repair shops and technicians, e-waste recyclers, electronics manufacturers (EPR obligations), and the wider environment and society.

Objectives

  1. Give users an instant, explainable repair-or-replace recommendation with cost, savings and CO₂e estimates.
  2. Connect users to nearby repair, refurbish, collection and recycling partners.
  3. Make booking and tracking a repair or recycling pickup simple and transparent.
  4. Enable reuse through a marketplace for tested parts and refurbished devices.
  5. Measure impact (e-waste diverted, CO₂e avoided, money saved) from completed actions only.
  6. Promote safe practice: data wiping, battery and cable hazards, authorised recyclers only.

4 System architecture

TechCycle is a client-side single-page application organised in three layers. The presentation layer holds the six modules. The application logic in engine.js is written as pure functions, so it can be unit-tested and later moved to a server unchanged. The data layer, store.js, is the only module that touches storage, so swapping browser storage for a REST API in Milestone 3 changes a single file.

5 User workflow

The engine's verdict sends the user down one of three paths. Each path ends in an outcome that is counted on the impact dashboard: a device kept in use, a completed repair or a certified recycling.

6 Data flow diagram (Level 1)

The diagram shows two external entities, five processes and five data stores. D1 is read-only reference data used by the assessment, request and impact processes. Impact is computed from stored requests and checks, never typed in by hand.

7 Data model

The prototype stores these entities as JSON in the browser. The same schema will map directly to database tables in Milestone 3.

8 Request lifecycle (state machine)

Each request moves through a fixed sequence of states. Only the partner console can advance a request. The user can cancel, and the partner can decline, only while it is still Submitted. A repair cannot be marked Completed without a final cost.

9 Decision engine design

We chose a transparent weighted-scoring model over machine learning for this stage. We have no labelled dataset of repair outcomes yet, and users and faculty can check every factor behind a rule-based score. Each recommendation shows the three factor values and the reasons in plain language.

score = 100 × (0.55 × C + 0.25 × A + 0.20 × S)

C (cost) = clamp(1 − (estimated repair cost ÷ new device price) ÷ 0.5, 0, 1)

A (age) = clamp(1 − device age ÷ typical lifespan, 0, 1)

S (success) = typical success rate for that fault (0–1)

VerdictRuleWhat the user is offered
Try the free fix firstA safe, free fix exists (e.g. software slowness, Bluetooth pairing)Step-by-step tips, then a repair booking if the fault persists
Repair itscore ≥ 60Book repair, find a repair shop
Worth a repair quote40 ≤ score < 60Book a diagnosis and compare the quote
Recycle responsiblyscore < 40Data-wipe checklist, recycling pickup, refurbisher buy-back

Built-in 50% rule. If a repair costs half the price of a new device or more, C becomes 0 and the score cannot exceed 45, so the engine never says “Repair it”. The test suite checks this property across every device, tier, fault and age combination.

Reference data and assumptions

All prices, cost shares and footprints are indicative prototype assumptions, kept in one file (js/data.js). Device footprints are order-of-magnitude manufacturing-phase values drawn from manufacturer product environmental reports and LCA literature. In Milestone 3, repair-cost shares will be calibrated against real quotes from partner shops. This table is generated from the same data the app uses.

  • A completed repair is assumed to replace the purchase of one new device of the same segment. CO₂e avoided = manufacturing footprint × 0.9, since 10% is allowed for replacement parts.
  • Money saved = new price − final repair cost. Recycling counts device weight as e-waste diverted, but no CO₂e credit is claimed.

12 UI design

Screens

  • Home: boot animation, rotating globe, problem statistics with sources, circular-economy loop, module overview, SDG mapping.
  • Check device: four-step form → score gauge and explained verdict.
  • Find services: map + distance-sorted partner cards.
  • Book & track: booking form with live estimate → request ID → timeline.
  • Parts market: searchable listing grid + listing form.
  • Impact: KPI counters and charts.
  • Partner console: request cards with stage controls.

Design principles

  • Mobile-first: layouts collapse to one column with a slide-down menu.
  • Accessible: labelled inputs, keyboard navigation, visible focus, ARIA live regions, colour plus text for every status.
  • Motion with purpose: animations show progress (gauge, timeline, counters), and all motion turns off when the device asks for reduced motion.
  • Honest UI: sample data and estimates are always labelled as such.
  • Light and dark themes share one set of colour tokens.

    16 Ethics, safety & privacy

    • Privacy by design: in the prototype all personal data stays in the user's browser, and nothing is sent to a server. Phone numbers are used only to identify a request.
    • Data protection on handover: recycling requires a confirmed data-wipe checklist (backup, sign out, remove SIM and SD card, factory reset).
    • Safety first: swollen batteries, liquid damage and frayed cables trigger explicit warnings. DIY tips are limited to safe, non-invasive steps.
    • Legal compliance: recycling is routed only to authorised recyclers, in line with India's E-Waste (Management) Rules, 2022.
    • Honesty: estimates are labelled indicative, sample partners and listings are marked “sample”, and demo records are marked “demo”.
    • Inclusion: rupee pricing, a mobile-first and low-bandwidth design, Hindi names accepted in forms, and accessible controls. Hindi UI is planned.
